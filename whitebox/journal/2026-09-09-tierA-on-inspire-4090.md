## 4. E2：`mean`/`mismatched` 的 logprob 比 real 高，答案是「off-manifold 抬升」

§12.3w 埋下、§12.3y 接上读数的两个预注册判据，这一跑第一次有数据。

聚合 recovery（logprob）那一列，层 21–27：

```
  layer       real mismatch mean vec   filler
     21       1.47    -3.25     5.43     2.78
     22       0.95    -4.05     4.71     3.37
     ...
     27       1.00    -4.32     6.41     3.03
```

`mean` 和 `filler` 都比 `real` 高。**但准确率是反的**（层 21）：real 0.436、
mean 0.282、filler 0.205、mismatch 0.205。

mass / margin 分解给出机制（`mass` = log P(下一个 token 是某个选项字母)，
`margin` = lp(gold) − max(其余三个)）：

```
  --- layer 19（准确率峰值，落在打坏区间里）
  condition      n      mass    d mass    margin  d margin      acc
  no doc        39    -0.000    +0.000    -5.966    +0.000    0.231
  with skill    39    -0.019    -0.019    -2.491    +3.475    0.436
  real          39    -0.000    -0.000    -2.740    +3.226    0.462
  mismatch      39    -0.000    -0.000    -4.336    +1.630    0.385
  mean vec      39    -0.000    -0.000    -7.231    -1.265    0.231
  filler        39    -0.077    -0.077    -4.172    +1.794    0.256

  --- layer 21（预先定死的层）
  real          39    -0.038    -0.038    -2.345    +3.621    0.436
  mismatch      39    -0.054    -0.054    -7.350    -1.384    0.205
  mean vec      39    -0.000    -0.000    -2.817    +3.149    0.282
  filler        39    -0.188    -0.188    -3.981    +1.986    0.205
```

**判断**：
- **层 19 上 `mean` 的 margin 是 −1.265**，即它在「选」，而且**选反了**。
  配合它 +5.4 的 recovery：它把 gold token 的概率抬上去了，却没让 gold 变成 argmax。
  `e2_acc.py` 自己的判词就是这个：*"It lifts the gold token's probability without
  making it the argmax, which is what an off-manifold direction does."*
  **所以「mean 比 real 高」是真实存在且可解释的，不是偶然：聚合 gold logprob 在
  这里不是行为的代理量。**
- **层 21 上 `mean` 的 margin 变成 +3.149（文档的 91%），准确率却只有 0.282。**
  这一层它确实在「选」，方向也对，但力度不足以让 argmax 过线。所以 mean 的异常
  **不是一个恒定现象，而是分层的**：层 19 选反、层 21 选对但不够。
- `mismatch` 在层 21 的 margin 是 **−1.384**，正是 §12.3y 预测的 mismatched 形状
  （「纯扰动会把 margin 压平而不是压负」）。

## 5. 最直接的内容证据：别题向量把**供体那道题的答案**写了进来

```

        argmax == DONOR's gold    11/39  = 0.282   p=0.380 against 0.25
        argmax == its OWN gold    15/39  = 0.385
      At chance.

  --- does the mismatched vector carry the donor's answer?   (layer 21)
        argmax == DONOR's gold    16/39  = 0.410   p=0.020 against 0.25
        argmax == its OWN gold     8/39  = 0.205
```

**层 21 上 p=0.020**。这是整个研究里**关于内容最正面的一条证据**：尾部那个向量里
装着供体那道题的答案，而不只是「有份文档在」这个状态。层 19 上是随机 —— 又一次
说明打坏区间里读不出东西。

## 判断（每条注明依赖哪个数）

1. **差向量有效，但不完整。** `add_diff` 在 13 题上最高 **0.769（10/13，层 26–27）**，
   整体准确率最高 0.462（层 18/20），**与真 skill 的 0.436 持平**。
   而 `replace_real` 在层 24–27 是 **1.000**。
   → 内容成分**可分离、可加**，但整段状态里还有别的东西也在起作用。

2. **`add_generic` 每一层都是 0.000。** 这是让第 1 条有意义的对照：
   被减掉的那部分（`h_fill − h_no`，即「有份文档在」）**一道题都修不好**，
   而且在层 21–27 把整体准确率压到 0.154–0.179，**低于无文档基线 0.231**。
   → 减法减掉的正是不起作用、甚至有害的那部分。

3. **逐题特异性从层 21 开始。** `add_diff_shift`（别题的差向量）在层 18–20 是 0.462，
   和 `add_diff` 的 0.538 差不多；层 21 起崩到 0.154–0.231。
   → **用一个和 E2 完全不同的干预方式，独立复现了「层 19 共享 / 层 21 逐题」**。
   这一条重要：E2 的同一结论此前只有一种测法支持。

4. **一个共享的内容方向不够。** `add_diff_mean` 在层 21+ 只有 0.077–0.154。
   → 对 H2（skill 只是选中已有能力，可压成单个向量）不利；对 H1（内容检索）有利。

5. **层 18 起 `cos(d, h_no)` 变负**（+0.159 @16 → −0.229 @21）。
   内容成分在晚层是**逆着**接收方自身状态的方向，不是「在原方向上加强」。

6. **层 18–20 上 `add_diff`（0.538）反而超过 `replace_real`（0.385–0.462）。**
   在打坏区间里，加差向量比整体替换好 —— 合理的解释是替换把通用成分和
   「打坏」一起搬了过来，而减法把它留在了原地。**这是打坏区间存在的又一个独立证据。**

## 当时不确定的

- **层 21 的 0.538 与层 26–27 的 0.769 之间那个上升**：是内容真的越晚越可读，
  还是晚层的写入更接近输出、更容易压过原有计算？`replace_real` 有同样的形状
  （0.923 → 1.000），而 §12.3x 第 5 条已经警告过层 24–27 的 1.000 可能是写穿。
  **只引用层 21–22。**
- `alpha` 只跑了 1.0。剂量反应（0.5 / 2.0）没测，所以"可加"这个说法目前只在
  alpha=1 上成立。
- n=39，13 题的分组里 0.538 与 0.769 之间差 3 题。**不要把这两个数当成不同的量级。**

# 追加：E12 题目 span 移植 —— 三个窗口接上了（`20260909-130000/e12-tierA`）

新脚本 `e12_taskspan.py`。**预注册写在跑之前**（见脚本头部和 commit `a3c7db3`）：
如果内容是「skill span → 题目 span → 最后一个位置」这样接力的，那么补题目 span
应当在一个**比 E10 晚、比 E2 早**的窗口里有效。

接收方和 E10 完全一样（skill 的 token 换成等长 filler 切片，长度相同、span 外逐 token

## 判断

**1. 三个窗口有序且基本不重叠。** 把同一批题、同一个模型、同一套自检下的三条曲线并排：

| 实验 | 补的位置 | 有效窗口 | 峰值 acc | 接收方基线 |
|---|---|---|---|---|
| E10 | skill 自己那 688 个 token | **0–10** | 0.436（L3–4） | 0.154 |

E12 在层 10 是 0.231，层 11 升到 0.308、层 12 到 0.333。

E12 层 22–27 的 |recovery| < 0.05、acc 精确等于接收方基线 0.154。

→ **合起来是一个三段接力**：内容先留在文档自己的 token 上（≤10），
再经由题目的 token 中转（11–16），最后被摘要进最后一个位置（21+）。

## 分寸

- **E12 的峰值 0.333 低于 E10 的 0.436 和 E2 的 0.436–0.487。** 题目那几十个 token
  单独承载的比整份文档或最终摘要少。这是**部分**接力，不是全部经由这条路。
- **天花板（28 层一起换）= 0.333，等于单层峰值。** 和 E10 一样，全换没有额外收益。
- n=39。0.333 与 0.308 差一道题，**窗口 11–16 是实的，窗口内峰值的位置不是**。
- 层 17–20 上 E12 在下降而 recovery 转负 —— 那是 §12.3t 的「前向被打坏」区间，
  这里又一次看到它，且方向一致。

## 顺带：self 臂是比 patchcheck 更干净的 bf16 探针

第一次跑 E12 时忘了给 dtype（直接调脚本会落回 `WB_DTYPE` 默认的 bfloat16），
self 臂读出 **0.661 nats** 偏差并触发了它自己的警告。改成 `--dtype float32` 之后
是 **0.000000**。

self 移植在代数上是精确空操作，**真值按构造就是零**，不需要第二次跑来定义。
所以它比 `patchcheck.py` 更直接地量出了 §12.3q 那个 bf16 误差：
**捕获前向跑的是 prompt、打分前向跑的是 prompt+答案，两者长度不同、归约顺序不同。**
`e12_taskspan.py` 现在有显式 `--dtype`，帮助文本里写了这件事。

# 追加：E13 注意力路由 —— 「接力」这个说法要收窄（`20260909-130000/e13-tierA*`）

新脚本 `e13_route.py`。E10/E12/E2 说的是内容**在哪里**；移植只证明某个位置的状态
**够用**，不证明模型真的走那条路。在 decoder 里能把内容跨位置搬运的只有注意力，
所以直接屏蔽它。五个臂，每个是注意力矩阵上的一块**矩形**（查询区间 × 键区间）：

```
all_to_skill     所有查询      -> skill span      （E1 的形状，作标尺）
q_to_skill       题目 span     -> skill span      （接力假设）
last_to_skill    最后一个位置  -> skill span      （直读假设）
q_to_nonskill    题目 span     -> 题目之前的非 skill 部分（preamble+glue）
lastq_to_skill   一个与题目等宽、位于 skill 之后的查询窗口 -> skill span
```

## 第一次跑（单层敲除）测到的是零，而且那是真零

`--sweep single`。**准确率通道几乎全平**，而**精确匹配的对照 `lastq_to_skill`
在几乎每一层都读出 0.436 = 未屏蔽基线**。所以那些零是**这个功效下的真零**，
不是仪器坏掉。

原因是结构性的，不是缺陷：**skill 有 688 个 token，内容在层间冗余可读**——
在第 L 层不给读，模型在 L+1 层读。这正是 §12.3u 记的「E1 不是坏的，是功效不够」，
只是这次用一个更细的仪器看到了同一件事。

**同一次跑里发现的一个对照 bug**：`q_to_random` 的键区间按「与 skill 等宽、
从位置 0 开始」构造，而这条 prompt 的排布是
`[preamble][skill 688][glue][question 45][suffix]`，所以那个窗口
**把整个 skill span 吞了进去**——「对照」屏蔽的严格多于处理组，自然更伤。
**那一版的数字作废。** 修法不是造一个假的等宽对照（这条 prompt 上不存在
与 skill 等宽的非 skill 区间），而是照实命名不对称：`q_to_nonskill` 就是
preamble+glue，只当方向读，不当匹配地板。**承重的对照是查询侧那个**，它是精确匹配的。

## 判断

**1. 干预确实做到了它声称的事（内建合格性检查）。**
`all_to_skill` 从层 0 起全屏蔽 → 准确率 **0.205**，而无 skill 基线是 0.231。
把所有位置对文档的注意力挡掉，skill 的全部收益就消失了。
这个检查以前没有过 —— E1 从来没报过「全挡掉等于没给 skill」。

**2. 模型对这份文档的读取在层 21 就结束了。**
从层 22 起屏蔽，**五个臂、两个通道全部代价为零**（|Δlogprob| < 0.11，
准确率精确等于 0.436）。而且从层 18 起，即使全屏蔽也只差 0.026（0.410 vs 0.436）。
→ **收益在层 18 之前基本已经建立完毕。**
这和 E2/E11 说的「层 21 上最后一个位置的状态既充分又逐题特异」是同一件事的两面：
层 21 是它**最后一次还需要读**的层。

**3. 「接力」这个说法必须收窄：没有哪条通路是必需的。**

| 从层 0 起屏蔽 | 准确率 |
|---|---|
| 什么都不屏蔽 | 0.436 |
| 只屏蔽 **题目 span → skill** | 0.282 |
| 只屏蔽 **最后一个位置 → skill** | **0.436**（毫无代价）|
| 屏蔽 **所有位置 → skill** | **0.205**（= 无 skill）|

**只有全屏蔽才拿掉收益。** 拿掉任何单一位置组，剩下的位置都还够。
→ 读取是**冗余分布**的。

**这与 E12 不矛盾，两者合起来更锋利**：
- E12（移植）证明的是**充分性** —— 题目 token 在层 11–16 的状态**足以**转移效应；
- E13（敲除）证明的是**非必要性** —— 题目 token 对 skill 的注意力**不是必需的**。

**所以三个窗口追踪的是「内容积累到了哪里」，不是「内容走了哪条唯一的路」。**
论文和汇报里都要按这个措辞写。**我先前那句「三段接力」是过强的，已按此修正。**

**4. 两个通道又一次分歧，而且这次方向相反。**
logprob 上，从层 17 起 `last_to_skill` 与 `all_to_skill` 逐位几乎相同
（L21：−1.669 vs −1.682），像是「晚层只剩最后一个位置在读」；
准确率上它们不同（0.410 vs 0.410 在 L21 相同，但 L0 是 0.436 vs 0.205）。
按本研究一贯的规矩：**分歧本身是结果**，两条都报。

**5. `q_to_skill` 在早层屏蔽反而让 logprob 上升 3.4 nats。**
不要拿它当结论。这批题上 logprob 通道已知不追踪行为
（中性文档把 gold logprob 推得比 skill 还远，+2.23 对 +0.64），
这条大概率是同一个毛病的又一次现身。准确率上它是 0.282，低于基线。
