# 2026-09-03 末层恒等：把 1.265 拆到底

`experiment.sh` 跑 `20260902-100854`，两个 e2 阶段都打出
`末层恒等检查 ... 恢复率 = 1.265 (要 1.000)`。§12.3p 的修补把它从 4.09 拉到
1.265，但没到 1.000。这一篇是把剩下那部分拆开的过程。

## 先确认哪些数没变

E2 报的数一个没动（最佳层 21、real +1.651、filler +3.222、mean +5.590、
mismatched −3.764）——只有末层的捕获点变了，而末两层本来就被 `TAIL = 2` 排除。

E7 的 Tier A 数字**变了**，明细进了 §12.3q。要点：`filler` 峰值层 6 → 27，
「filler 峰在早层」那条对比撤回；跨文档余弦 +0.95 不变，E7 主结论不动。

## 判决序列

`patchcheck.py`，8 题，1.7B：

```
[OK ] 1. 金答案是单 token: 'A' -> 1 个 token [32]
[OK ] 2. hidden_states[-1] 是 post-norm: True
[OK ] 3. norm(捕获到的向量) == hidden_states[-1]: True   max|diff| 0
[4] 逐题恒等   mean +0.3979   同号 3/8 为正
     0000 diff +4.0000   0007 diff -1.8762   0004 diff -0.0046
[OK ] 4b. 补丁位置上的 logits 与源前向相同: True   max|diff| 0
[BAD] 6a. answer_logprob(yes) == log_softmax(源前向最后一行)[金 token]: -10.5000 vs -14.5000
[OK ] 6c. 同一个调用跑两次相同
[BAD] 6d. 追加答案 token 后同一行仍相同: max|diff| 3.188  (金 logit +38.000 vs +40.500)
```

**4b 是 `max|diff| 0`**：补丁通路逐位正确，「捕获点和写入点不是同一个东西」排除。
**6a 不涉及任何补丁**：两个普通前向，只差一个 token，就已经差 4 nats。

判断依据是差的**结构**，不是大小：差跟着 |lp| 走——gold 在尾部的题差 0.5~4，
gold 就是 argmax 的题差 ≤0.005。纯 bf16 舍入会在八题上均匀撒开，不会挑着尾部炸。

## fp32 定案

```
[4] 逐题恒等   全 8 题 diff +0.0000
[OK ] 6d. max|diff| 0
[7] 逐层相对偏差   每一层 0.00%
```

对照 bf16 的检查 7：层 0 是 0，层 3 是 0.09%，层 12 是 0.78%，层 21 是 1.09%，
**末层 11.11%**。末层那个跳变是分母造成的——绝对偏差 8 → 32，而该行
`max|h|` 从 776 掉到 288。

**不是 bug，是 bf16 的算术。** 判定规则（写在脚本里的）按预期工作了：
「层 0 起平滑增长 + fp32 塌到 0」= 算术；「某层突跳 + fp32 不动」= bug。

## 副产品：一个比恒等检查更要紧的问题

bf16 的 `lp_yes` 对 fp32 的误差：0000 −2.53、0007 +0.94、0003 −0.58、
0002 +0.53，而 lp≈0 的三题 ≤0.01。**gold 躺得越深，误差越大。**

这波及所有 logprob 类结论，不只 E2，而且配对 bootstrap 不覆盖它。
处理见 §12.3q：梯队 a 改 fp32，梯队 b 先量再定。

## 一个方法教训

前两轮都在「排序自己觉得最可能的原因」，第三轮改成「把每一环单独查一遍，
第一个 BAD 就是答案」，一跑定位。**4b 那种近乎同义反复的检查最值钱**——它一次
就把一整个假设族（补丁通路坏了）删掉了，代价是四行代码。
