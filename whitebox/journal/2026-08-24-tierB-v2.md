## 2. 判断，以及各自依赖哪个数字

### 2.1 v1 死在地板上，v2 死在天花板那一端

依赖 `准确率 0.819` 和 `随机水平 0.25`。无 skill 已经 81.9% 对，**余量只有
18.1pp**。§2 的任务集要求是"无 skill 准确率不能接近 0 或 1"，v1 是前一半
（0.067），v2 是后一半。**换题解决了算术那个混杂，同时把基线推过了头。**

这件事有一个硬后果，跑之前没有人算过：准确率那一档门槛要 Δ≥15pp 且 CI 下界 >5pp，
在 0.819 的基线上等于要求 skill 修好剩下错题的 **83%**。那一档在这份题集上
**够不着**，所以"未通过"在这里首先是关于题的事实，和 v1 一样。

> 这一跑之前，`report.py` 对 0.819 这个基线一个字都不会说：地板告警挂在
> `acc_no_skill < 0.10` 上。现在 `e0_effect.py` 和 `report.py` 都会在余量 < 20pp
> 时打印这条，并算出那个 83%。

### 2.2 常数那份差一点点，方法那份是干净的零

依赖两行 logprob CI。const：Δacc +6.9pp 已经过了 logprob 通道的前置条件（≥5pp），
卡在 **CI 下界 −0.008**——差 0.008。配对 +12/−4、Δlogprob +0.494 方向一致。
**它不是零结果，但也没被确认**，两句话都要说。

proc：+0.9pp、Δlogprob −0.024、配对 +5/−4，两档都没够。这是一个干净的零。

**不要在同一批题上重测 const。** 门槛差 0.008 就再跑一次是按结果选测量，
n=116 已经是整个题池，唯一诚实的杠杆是**多生成题**（外加把题变难，见 2.1）。

### 2.3 双重分离没有成立，而且不是"一半"那么简单

依赖 `pchem-constants: 单位轴 11, 关系式轴 1` 和 `pchem-procedure: 单位轴 4,
关系式轴 1`。

- 常数那份：12 题里 11 题落在**它自己的轴**（单位轴）。方向和预注册一致。
- 方法那份：5 题里 4 题落在**单位轴**——那是它按构造碰不到的轴，
  `SKILL.pchem-procedure` 里一个常数都没有。

所以准确的说法不是"分离了一半"，是：**一份 skill 有（未被确认的）效应且落在自己的
轴上，另一份既没有效应，它那几题也落在别人的轴上。** 5 题的比例不稳定，当方向读，
不要当比例读。

汇总当时打的是"只分离了一半"。这一轮把 `report.py` 改成会额外指出"某份 skill 修好
的题多数落在它按构造碰不到的轴上"，并在两对 e0 都没过门槛时明说"下面是在拆一个还
没被确认的效应"。

### 2.4 E7 是这一跑里最强的信号，也是控制最弱的一个

依赖四个数：两份 skill 的峰值层**都是 15**、`||d||/||h||` **0.523 / 0.519**、
逐题余弦 **+0.98**、有效维数 **1.0/116**，以及两份之间的方向余弦 **+0.97**。

读作：注入在峰值层写进去的基本是**一个方向**（116 题的有效维数是 1.0，逐题余弦
0.98），而且**两份内容不重叠的文档写的是同一个方向**（0.97）。行为层看到的
（一份修单位轴、一份什么都不修）和表示层看到的（两份几乎同一个方向）不是同一件事。

**但是这个 run 里没有中性对照。** 一份等长的、与任务无关的文档会不会也产生同一个
方向？没测。所以"注入有通用签名"和"上下文里多了一份长文档"现在**分不开**，
0.97 支持不了前者。`tasks/filler-neutral.md` 早就在仓库里，`e7_repr.py` 的
`--skill` 本来就可以给多次——这一轮把它加进了 `run-whitebox.sh` 的两个 e7 阶段，
下一跑就有第三条曲线。

### 2.5 层间实验没跑，是对的

依赖交叉校验最后一行 + 两条"门槛未通过"。恢复率的分母是行为效应差值，两对都没过
门槛，`run-whitebox.sh` 按 §13.2 跳过 e1/e2 是设计行为，不是故障。
