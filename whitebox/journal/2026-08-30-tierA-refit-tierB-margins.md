## 判断，以及它依赖哪个数字

### 1. §12.3m 的两条预注册都命中

- **基线回到随机**：0.085 → **0.231**，随机水平 0.25。echo 陷阱确实是那个 −0.165。
- **Δacc 变小**：+36.2pp → **+20.5pp**。预注册说「变小是预期的、也是好事」，因为
  剩下的那部分才是关于查表的。

### 2. 但 Tier A 现在过不了自己的门槛 —— 这是这一跑最要紧的新问题

Δacc **+20.5pp，CI95 [0.0, 41.0]**（准确率那一档要下界 >5）；
Δlogprob **+0.641，CI95 [−2.260, +3.559]**（logprob 那一档要下界 >0）。两档都没够。

点估计不小，**是区间宽**。§12.3m 已经预告过：「39 题的 CI 会比 47 题更宽」。
n=39 的正对照现在没有足够的功效去确认它自己的效应。

**后果不是「Tier A 白跑了」，是「Tier A 上所有的恢复率没有分母」。** e2-tierA 的
+1.651 是除以 +0.641 得来的，而 +0.641 的 CI 含 0 —— 那个比值没有定义。这一跑
里它还没被标记（代码只给 Tier B 挂了 `--gate-unconfirmed`），已修。

**杠杆是加题**，不是调分析：`tier_a/build.py` 里 `for value in (2,3,4,5,6)` 放宽
就能把 39 拉到三位数。§12.3m 里写过这是唯一诚实的做法。

### 3. §12.3n 的第一条预注册落进了一个没准备的格子

预注册的是 `R = Δacc(filler) / Δacc(skill)`，三档以 1/3、2/3 分界，我们赌第一档。
实测 R = −7.7 / 20.5 = **−0.38** —— **filler 把准确率推向了反方向**。预注册整套
是按「filler 的 Δacc 为正、只是比 skill 小」写的，负值没有位置。

按字面这是「第一档」（内容余量 +28.2pp，比 skill 自己的效应还大），`report.py`
当时也确实打了「主体是内容」。**那句话是错的**，有两条独立的理由：

- **可解析率 100% → 85%。** filler 让 6 题（15%）答不出字母来（`unparsed` 0 → 6）。
  它掉的分里有一大块是格式，不是内容。余量被这一块抬高了。
- **logprob 那条通道说的是反话。** filler 的 Δlogprob 是 **+2.194，CI [+0.798,
  +3.673]，不含 0**；skill 的是 **+0.641，CI 含 0**。**中性文档把金答案 token 推得
  比 skill 还远，而且只有它是显著的。** 准确率只是同一个分布上的阈值读数。

**诚实的结论：Tier A 上中性文档不是惰性的，它是往另一个方向破坏。**「内容占多少」
在这一梯上目前判不了 —— 两条通道给出相反的答案，而准确率那条的对照有格式问题。

三条护栏已经写进 `report.py`（负 share、可解析率、logprob 通道）。

### 4. §12.3n 的第二条按字面失败，但按设计意图成立 —— 而且比原来更强

预注册：「filler 的轴间距 delta，CI 应当含 0」。实测 Tier B 的 filler：

```
常数轴  -2.270  CI [-3.047,-1.484]   不含 0
关系式轴 -2.263  CI [-3.034,-1.514]   不含 0
两轴    -2.641  CI [-3.350,-1.917]   不含 0
```

**三条全部显著为负。间距对「上下文里多了份长文档」并不免疫** —— 一份中性文档把
金选项相对**每一个**干扰项的优势都压掉约 2.3。§12.3l 那句「共同位移等量抬高两项，
相减消掉」在这里不成立。

**但 did.py 用的不是间距本身，是 lean —— 两条轴的差。** filler 的两条轴：
−2.270 与 −2.263，**相差 0.007**。也就是说这个压制在两个轴上几乎完全等量，
**lean 对它免疫**。预注册检查的是错的那个统计量。

这不是「侥幸过关」：它把一个**假设**换成了一个**测出来的零点**。原来 lean 的零点
是靠论证（间距该免疫）；现在有了 filler 的 lean ≈ −0.007，对着 constants 的 +1.449
和 procedure 的 +0.723 读。**§12.3n 的这一条应当改写成：查 filler 的 lean，不是
查它的间距。**

### 5. Tier B 给出了第一个带区间的预注册判词：**只分离了一半**

### 6. 轴间距确实解掉了天花板问题 —— 有直接证据

`e0-tierB-proc`：**准确率 +0.9pp（什么都没有），而三条轴间距全部显著为正**
（+1.144 / +1.867 / +1.308）。同一份文档，在准确率上是零，在间距上不是零。
§12.3l 换因变量的理由（「本来就答对的题，间距照样能拉宽」）在这里被直接看到了。

### 7. E2 的那条结论在新题集上**没有**被推翻 —— 反而更强

§12.3m 列的「受影响、且只有 Tier A 一处证据」的就是这条。新题集上：

```
K=1   real +1.651   filler +3.222   内容余量 -1.571

```

**中性文档的向量比 skill 的向量恢复得更多。** 旧题集上余量是 −0.003（打平），
现在是 −1.5（filler 明显更好）。所以那条结论不是 echo 陷阱造出来的。
平均向量（不含任何逐题内容）+5.59 仍然最好，别题向量 −3.76 仍然最差。

Tier B 那边是另一个方向：`e2-tierB-const` 的内容余量 **+0.518**（filler 恢复得少）。
两梯不一致，而两个分母都未确认，所以这一对**只能当线索**。

### 8. 错误类型学换了故事：Tier A 修的是**选择**，不是检索

旧题集：84% 来自 echo（engagement）。新题集没有 echo 选项，修好的 13 题：

```

wrong_row     2 (15%)   ← 读对表读错行   H1 检索
inverted      1 ( 8%)   ← 方向反了       H2 选择
```

**85% 是选择，15% 是检索。** 同时 `wrong_row` 从 6 涨到 13 —— **skill 把人从「选错
表」搬到了「选对表但读错行」**。轴间距是同一个形状：选错表那条轴 +7.337（不含 0），
读错行那条 +0.037（含 0）。

（这个数是修完 `errors.py` 才读得出来的：`option_kinds` 加到 Tier A 之后，
`tier_b2` 的判定把 Tier A 切到了 Tier B 的读法，那一档打出来是「0% 单位轴，
0% 关系式轴」。见本次提交。）

### 9. E7 在两梯上一致：注入方向是通用的

Tier B 三份文档**峰值层全是 15**、‖d‖/‖h‖ 0.52–0.55、逐题余弦 0.98、有效维数
1.0/116，两两余弦 0.94–0.97（含 filler）。Tier A 的余弦 +0.95。

1.00 和 1.0。skill 的方向比 filler 多一点逐题结构 —— 小，但方向对，是 v3 要放大的

### 10. 还没解决的三条

## 当时不确定的事

1. **Tier A 加到 100 题之后，+20.5pp 会不会站住？** 点估计不小，但 CI 宽到没法用。
   这是唯一能让 Tier A 重新当正对照的动作。
2. **filler 在 Tier A 上为什么会让 15% 的输出答不出字母？** 一份结构相似、任务无关
   的文档不应该破坏格式。要看 `per_item.jsonl` 的 raw —— 也许是长度，也许是那份
   文档的排版把模型带进了别的输出风格。它同时污染了「内容余量」的分母。
3. **两梯的 E2 内容余量符号相反**（Tier A −1.57，Tier B const +0.52），是模型规模
