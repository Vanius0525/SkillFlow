## 2. 逐条判断，以及它依赖哪个数字

### 2.1 E7：中性对照和 skill 分不开。依赖那三个余弦，和 filler 的 0.549

三对方向余弦 +0.972 / +0.945 / +0.955，**几乎一样高**。而且 `filler-neutral`
自己的四个量和两份 skill 逐项同形：同一个峰值层 15，逐题余弦 +0.983，有效维数
1.0/116，PC1 占 33.0%。**它的 ‖d‖/‖h‖ 是 0.549，比两份 skill（0.523 / 0.519）
还大。**

所以 §12.3i 第 4 条那个疑虑坐实了，而且是最坏的那一半：**E7 现在这个观测量
（prompt 末位 residual 的平均差向量）测的是「上下文里多了一份长文档」，不是
「这份文档说了什么」。**

一条要留意、但不能过度解读的细节：skill–skill 的 0.972 **确实**高于两个
skill–filler（0.945 / 0.955），差 0.017–0.027。方向是对的（内容相近的文档应当更
对齐），但**每个条件只有一个平均方向，没有误差棒**，这个差值现在读不出显著性。
逐题 `d_i` 都已经落盘了，**按题 bootstrap 出这三个余弦的 CI 是几分钟的事**，
应该做——这是把「有没有一个小的内容特异成分」从猜测变成测量的唯一便宜办法。

### 2.2 离域负对照：负对照本身合格，但跨条件比较是脏的

`+4.3pp` CI 含 0，logprob **−0.175** CI 含 0。作为负对照这是**正确的表现**：
两份 skill 都不覆盖的领域上，没有效应。

诱人但**不能直接做**的一步比较：域内 const 的 logprob 是 **+0.494**，这里是
**−0.175**，符号相反，看起来正好说明「域内那个位移是内容特异的、不是文档存在效应」。
**这个推论现在站不住**，三个混杂同时存在：

- **mode 不同**（域内 `mc` 四选一，离域 `num` 自由数值）——logprob 的量纲就不同
- **题集不同**（v2 生成题 vs v1 SciBench 原题）
- **基线不同**（0.819 vs 0.188，而 0.188 是撞在 v1 那堵算术墙上）

正确的表述是：**离域负对照自己通过了，但它还不能用来回答 E7 提出的那个问题。**
要回答，需要 §15.6 自己写的那个东西——**v2 格式的离域对照**（同样的 2×2 选装置
结构、同样 `mc`、换成两份 skill 都不覆盖的领域）。这件事现在是最高优先级的题集工作。

### 2.3 Tier A：之前那句「修好的 19 题 100% 来自检索错」是错的

新的分解：19 题里 **16 题（84%）来自 `echo`**，只有 3 题（16%）来自 `wrong_row`。
`echo` = 模型把题干里的数字原样抄了出来，**根本没在做这道题**。无 skill 条件下
47 题里 37 题（78.7%）是 echo。

所以 Tier A 那个 +36.2pp，**主体是「让模型开始尝试这个任务」，不是「帮它查对了表」**。

还有一个反向的数字容易漏掉：`wrong_family` 从 2 涨到 14。**skill 让模型开始做题的
同时，让它更多地选错表。** 这和 H5 是同一族的东西（文档里表多了，选错的机会也多
了），不是纯增益。`became wrong` 那 2 题全部落进 `wrong_family`，方向一致。

### 2.4 E6：H1 成立，之前的 `follow_rate = nan` 确认是抽取坏了

logprob 通道干净：`cf` 条件下 75% 偏向 cf，`true` 条件下只有 32.5%，
swing **+3.432**。**改掉文档里那一行，模型就朝那一行指的值移动——它在读那张表。**

生成通道则是废的：三个条件下 80%+ 的抽取结果是 `something else`，18% 抽到的是
**换算系数本身**（168 / 126 / 420），不是答案。§12.3g 那句「lp swing +3.43 指向
抽取坏了、不是 H5」到此确认，**不是** H5。

## 3. 四条合起来指向同一件事

单独看是四个负结果/零结果，合起来是一个正面的机制陈述：

1. **E7**：注入的表示层签名是**通用的**（filler 一样，甚至更强），一个方向，
   有效维数 1.0
2. **Tier A errors**：skill 的主要作用是把模型从「抄题干」切换到「尝试作答」——
   一个**模式切换**
3. **E2**（§12.3c，旧结果）：Tier A 上单个向量就能恢复 0.6–1.0
4. **E6**：与此同时，在 logprob 层面模型**确实在逐行读那张表**（swing +3.43）

前三条是同一件事的三个视角：**能压进一个向量、E7 看得见、Tier A 上效应最大的那个
东西，是一个「有文档在，进入作答模式」的通用状态，不是 skill 的内容。**
第 4 条说内容也在起作用，但它是**另一条通道**，而且小得多、E7 现在的观测量看不见。

这直接冲击一个之前当作已知的前提：**§3 E2 里「Tier A 的高恢复率是仪器灵敏度证明」
这句话要打折。** 它证明的是仪器能恢复**一个模式状态**——而模式状态本来就是最容易
压进单个向量的东西。它**没有**证明仪器能恢复内容特异的位移。

## 4. 当时不确定的、以及下一步该查什么

1. **E2 缺一个 filler 条件。** 这是这一跑最直接的代码后果：既然 E7 分不开 skill 和
   filler，E2 的恢复率很可能也分不开。**用 `filler-neutral.md` 的平均向量做一次
   补丁**——恢复得和真 skill 一样好，那 E2 现在报的恢复率测的也是「文档存在」。
   这个对照不加，E2 的所有数字都是有二义性的。
2. **三个余弦的 bootstrap CI**（§2.1）。逐题 `d_i` 已落盘，几分钟。
3. **v2 格式的离域对照**（§2.2）。现在排在改生成器前面。
4. **Tier A 的效应要分层重报**：在「本来就会尝试」的那 10 题上单独看效应，和在
   37 题 echo 上的效应分开。现在的 +36.2pp 是两者的混合，机制结论不能建在混合量上。
5. **`e0_effect.py` 不知道自己在跑对照。** 离域那一跑打印的是
   `GATE NOT PASSED. Try another task/skill pair.` —— 对负对照来说这是**反的**：
   没过门槛正是它该有的表现。加一个 `--control` 开关，让它把「没过」报成「符合预期」。
