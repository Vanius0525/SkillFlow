### 判断，以及各自依赖哪个数字

**基线低于随机不是格式问题。** 依赖 `可解析率 100% / 100%`。模型每一题都输出了
ABCD，0.085 是系统性选错而不是没答。所以 `[!] 基线低于随机 —— 先查格式再谈机制`
这条告警在这里是**误报**：它假设的原因被同一页上另一个数字排除了。推论是
+36.2pp 里没有 H3 的份额，比 §12.3b 当时估计的干净。

**skill 修的全是检索错，同时造出了选择错。** 依赖 `修好的 19 题来自 wrong_row
19(100%)` 和 `wrong_family 2(4%) -> 14(30%)`。模型手里从没有表变成有四张表之后，
新的失败模式是选错表。

> 由此得到一条对 E1 可证伪的预测：敲掉峰值层对 skill 的注意力之后，错误应当从
> `wrong_family` 退回 `wrong_row`（定位坏了），而不是退回随机（读取坏了）。

**E6 未定性。** 依赖两个口味 `都不是 100%` 且 `没答案 0%`。两种读法方向相反：H5
是结果，抽取失效什么都不是。倾向后者，依据是 **near(n=31) 和 far(n=40) 给出逐字节
相同的分布**——扰动幅度按构造差很远，行为效应不该完全一致。加上 errors 那条说明
这个模型爱回声输入的数字，而 `extract_num` 取的是补全里第一个数。

**汇总本身有缺陷。** 依赖四行 `(未知的 summary 格式)`。真正的代价不是少三段：
`cross_check()` 按 kind 取输入，全空之后 `if notes:` 为假，**整个交叉校验区块一行
都没打印**，而页面看上去是完整的。

### 判断

**两条都卡在 logprob 通道的前置条件上。** `lp_gate = d_acc >= 5 and lp_lo > 0`，
而 4.2 和 3.3 都不到 5pp，所以 logprob 那一档根本没被考虑到。层间实验按 §13.2 的
硬门槛跳过了；`e7-tierB` 跑了，因为它不需要行为差值当分母。

**这个零结果不可报告。** 依赖 `准确率 0.067`。§2 的任务集要求写着"无 skill 准确率
不能接近 0 或 1"，这次贴着地板。§13.3 预注册的"不过门槛也是可报告的发现"要求测量
**有余量**。现在能说的只是"这批题对这个模型太难"——关于题的事实，不是关于 skill 的
事实。

之前没有任何东西会指出这一点：`e0_effect.py` 的地板告警挂在"低于随机"上，而随机
水平只有 MC 模式才有，Tier B 是 num 模式。

**一个好迹象**：两次跑的无 skill 条件完全一致（准确率 `0.067`、logprob `-4.395`）。
这正是 §3 E2 要求的前提——constants 和 procedure 必须用同一批题。

## 3. 这一轮改了什么（commit `66ac30e`）

| 改动 | 起因 |
|---|---|
| `report.kind()` 加结构化兜底 | e1/e2/e7 把 `"experiment"` 写进了 `run-info.json`；兜底让**已跑完的 run 不用重跑**就能读 |
| 三个脚本 summary 补 `"experiment"` | 以后不靠推断 |
| 交叉校验区块**永远打印** | 空区块读作"没有矛盾",而真实原因是"没认出输入" |
| 未知格式打印键名 | 把"未知"变成可诊断的 |
| `fmt_e0` 打印 logprob CI95 | §2 定它为主因变量,而页面上只有点估计 |
| `e0_effect.py` + `report.py` 各判一次地板 | 见上面 Tier B 那条 |
| `fmt_e6` 正确处理 `nan` | 旧版把 nan 读成"混合——用逐题标签切分曲线",而一条标签都没有 |
| 新增 `e6_diagnose.py` | 分开 H5 和抽取失效 |
