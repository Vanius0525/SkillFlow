## 0. 一句话主张

> 一份 skill 文档对模型的作用，**不是**在某个位置注入了一个「技能向量」。
> 它的内容始终留在**文档自己的 token 上**，只在网络的前三分之一可以被整体搬走；
> 一个位置能搬走多少「决策」，由**答案占多少 token** 决定，而不是由内容多少决定。

三条互相独立的证据支撑它，正好是论文的三章：

| 章 | 问题 | 手段 | 结论 |
|---|---|---|---|
| A | 为什么大家都用的那个通道是死的 | 答案长度阶梯（同模型同题只换答案格式） | 单位置通道的容量 = 答案的 token 数 |
| B | 那么内容在哪 | 长度匹配的文档 span 移植 | 在文档自己的 token 上：0.00 → 0.95 |
| C | 那个向量是什么做的 | 在能通的通道里做完整因果臂 | 是 skill，不是 skill+task；不是共同偏移；不是范数 |

## 2. 1100 题（MedCalc + 55 个 gold calculator skill）上的发现，逐条

编号 M1–M12。每条给：**现象 → 数字 → 它排除了什么**。

### M1. 「有没有文档」本身没有用
gold 74.2% / no-skill 38.3% / **wrong skill 31.5%**。放一份不相关的文档比不放还差。
presence 效应 −1.3 pp，95% CI [−7.6, +5.7] 跨 0。
→ 排除「skill 只是提示模型要认真算」这类解释。后面所有分解都必须把 presence 作为控制减掉。

### M2. `ANSWER:` 提示词会把效应抹平，因此不能用它做因果
在 `\nANSWER: ` 提示下解码：none 0.175、wrong 0.175、gold 0.175 —— **三者完全相同**，
而同一批样本上 lp(gold answer) 仍然是 none −2.969 / wrong −2.928 / gold −2.368（+0.60 nats）。
来源：`probe-cue.jsonl`。
→ **这是一个实现层面的陷阱**：logprob 还在动，accuracy 已经死了。
  所有真实 skill 的因果实验一律 `--task-mode cot --max-new 900`（400 会截断）。

### M3. 最后一个位置的通道在 1100 题上是**完全死的**
`wb_diffvec`，cot 模式，n=40，R 格：gold 0.950、none 0.050，然后

| 臂 | L10/L14 | L20/L30 |
|---|---|---|
| `replace_gold`（整个状态换成 gold 的） | 0.125 | 0.025 |
| `add_d`（加内容向量） | 0.050 | 0.125 |
| `add_g`（加 presence 向量） | 0.025 | 0.000 |
| `add_d_samecalc` | 0.025 | 0.150 |
| `add_d_crosscalc` | 0.100 | 0.075 |

来源：`diffvec-cot-L1014.jsonl`、`diffvec-cot-L2030.jsonl`。
→ 没有一条臂离开 no-document 基线。**连整个状态整体替换都不行**，所以不是向量构造的问题。

### M4. 同一个 `d`，在文档自己的 span 上是**满效应**

`wb_spanpatch --matched`，n=40，四个 shard 独立复算基线且完全一致
（gold 0.950 / none 0.025 / receiver 0.175）。限制集（n=16）上的深度剖面，
按占可恢复区间的比例：

| 层 | 0 | 4 | **8** | 12 | 13 | 14 | **15** | 16 | 18 | 20 | 24 | 30 | 全层 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| ρ | 1.00 | 1.07 | **1.14** | 1.00 | 0.71 | 0.79 | **0.14** | 0.14 | 0.07 | 0.29 | 0.00 | 0.00 | 1.00 |

`self`（把接收器自己的状态写回去）在每一层都是 0.000 —— 仪器自检通过。
**L14 → L15 是一道悬崖：0.79 → 0.14。** 全层同时移植回到 1.00，
所以 L15 之后失效的是「一层的交接」，不是机制本身。

用另一种接收器（固定错误技能）重跑：L0/4/8/12 分别 1.00/1.07/1.14/1.00，
与上表一致；而 L20 的那个凸起（0.29）**没有复现**（复现值 0.16，低于它自己的 L16），
所以那是噪声。

→ M3 与 M4 是**同一个模型、同一批题、同一个分解**，差别只有「补在哪些位置」。

### M7c. 三个稳健性检查（最后一批）

**（a）剂量阶跃的位置定出来了：在 α=0.5 与 0.6 之间。**

| α | 0.25 | 0.5 | **0.6** | 0.75 | 1 | 1.5 | 2 | 3 |
|---|---|---|---|---|---|---|---|---|
| ρ | +0.00 | +0.06 | **+0.89** | +1.06 | +1.06 | +0.94 | +0.89 | +0.61 |

范数重标定的对照臂逐点落在原臂上（α=0.5：0.06 vs 0.06；α=2：0.89 vs 0.89），
所以**阶跃和衰减都与状态范数无关**。

**（b）calculator 数翻倍（10 → 20）后主结果复现。**
同样的限制后是 40 题 / 10 个 calculator（原来 20 题 / 5 个）：
`real` +0.95、`realm` +0.92、`dcross` +0.14、`drand` +0.08。
其中 `self`（仪器自检）读到 0.05 而不是精确 0 —— 40 题里有 2 题在「把接收器自己的状态写回去」
这个本该是恒等的操作下翻了。原因是 hook 强制了一次 clone，在 bf16 + 900 token 贪心解码下
会有极小概率改变轨迹。**这给了仪器自身噪声一个上界：约 1/20。**

**（c）F 格（gold 也救不回来的题）上，通道搬运的是文档的效应，不是正确性。**
n=40：gold 0.025、无文档 0.100、接收器 0.100、`real` 0.100、`dcross` 0.100。
`real` 跟着 `gold` 一起趴在地板上。**一条只会帮忙的臂无法和「让模型更努力」区分开；
这条臂在文档失效的地方也跟着失效。**

**（d）doc-last 下题目专属分量在任何深度都不起作用。**
L0/12/16/20 上 `dperp` 分别是 +0.00/+0.06/+0.00/+0.06，而 `dbar` 是 +1.06/+0.88/+0.82/+0.29，
始终跟着 `real`（+1.00/+0.94/+0.82/+0.35）。**不存在某个深度让「区分不同病历的那部分」开始起作用。**

### M7b. 一个被我自己抓出来的混淆：**「模型本来就会做这道题」污染了所有跨技能臂**（新）

用固定 filler 之后，`dcross`（另一个技能的向量）从 +0.07 升到 **+0.38**，看起来像「部分迁移」。
按 calculator 拆开看，它不是「部分」，是**双峰**：

| | 接收器从未解决过的 5 个 calc（n=20） | 另外 5 个（n=20） |
|---|---|---|
| 接收器 | 0.000 | 0.300 |
| gold | 0.900 | 1.000 |
| `real` | **+1.06** | +1.00 |
| `realm`（自己的 d，同样位置） | **+1.00** | +1.00 |
| `dnear`（**近亲**技能，同一个量的另一个公式） | **+0.00** | +0.71 |
| `dfar`（无关技能） | **+0.06** | +0.43 |
| `dall`（全体均值） | +0.11 | −0.14 |
| **`drand`（纯噪声）** | **+0.00** | **+0.14** |

→ **在另外那 5 个 calculator 上，连范数匹配的高斯噪声都能拿 +0.14，近亲技能能拿 +0.71。**
那里发生的根本不是迁移，是**扰动**：槽里那份错误文档才是把模型带偏的东西，
往上面写任何东西（有意义的或没意义的）都会把它搅乱，模型于是回退到自己已有的知识——而那是对的。

**处理方式：所有因果臂只在「接收器从未解决过的 calculator」上读。**
这个划分只依赖**接收器**（一个对照），不依赖任何干预臂，所以它不可能制造出它要报告的那个对比；
按 calculator 而不是按题划分，因为「模型会不会这个 calculator」是 calculator 层面的属性
（按题划分会留下 34/40，`dcross` 读成 0.39；按 calculator 留下 20/40，读成 0.06）。

限制之后**每一条结论都更锐利**（n=20，接收器 0.000，gold 0.900）：

| 臂 | ρ | | 臂 | ρ |
|---|---|---|---|---|
| `real`（α=1） | **+1.06** | | `dall`（共同偏移） | +0.11 |
| `a0.75` | +1.06 | | `dshuf`（乱序） | +0.11 |
| `normrecv`（重标定到接收器范数） | +1.06 | | `q2`（函数签名段） | +0.12 |
| `head`（前半段） | +1.06 | | `a0.5` | +0.06 |
| `realm`（共有前缀） | +1.00 | | `dfar`（无关技能） | +0.06 |
| `a2` | +0.89 | | `dcross` | +0.06 |
| **`q1`（公式段）** | **+0.80** | | `dnear`（**近亲**技能） | **+0.00** |
| `q3`（算例段） | +0.43 | | `drand`（噪声） | **+0.00** |

> 它同时说明了「错误文档的伤害来自它看起来像对的」（§A5），

### M8. doc-first 格式下，`d` 里**一点 task 信息都没有** —— 而且是逐位验证过的
文档排在问题**之前**，因果注意力下文档位置的隐状态只依赖 system + 文档本身。
同一个 calculator 的 4 道题文档逐字节相同 ⇒ `d` 是**同一个张量**。
第一次启动这组实验时数值上立刻显形：`dbar ≡ dpar ≡ real` 三条臂的滚动均值三位小数全同
（1.00/1.00/1.00、0.91/0.91、0.92/0.92），`dperp` 精确落在接收器基线。
**逐位验证（2026-09-11，不是推理，是量出来的）：**
- 同一 calculator 的 4 道题，文档 span 的 **token id 逐位完全相同**，绝对位置也相同
  （10 个 calculator，跨题配对共 0 个不同位置；span 一律从第 43 个 token 开始）。
- 把两条 prompt **截断到 span 末尾**后重新前向：`reldiff = 0.000e+00`，**逐位严格相同**。
- 完整 prompt 下 `h_gold` 跨题 `reldiff` = 3.5e-3（L0）/ 8.6e-3（L8），
  且 **cos<0.999 的位置数 = 0/778**。这是 bf16 在不同序列长度下选到不同 kernel 的累积舍入，
  不是内容差异。

→ 这不是负结果，是**结构性事实**：真正搬动一切的那个向量，**不含任何任务信息**。
  （同时它意味着：任何按题平均、按题相减的臂，在 doc-first 下都是恒等式，不是测量。见 §4-A1。）

| `dbar` | .900 | **+0.96** | 同技能其他题的 `d` 的均值 |
| `dpar` | .925 | **+1.00** | `d` 沿该均值方向的一半 |
| `dperp` | .250 | **−0.04** | 正交那一半（题目专属）＝ 接收器基线 |
| `dcross` | .275 | +0.00 | 另一个技能 |

| `dshuf` | .275 | +0.00 | 打乱 span 内位置 |

> ⚠ **这组数字推翻了用旧（被污染的）filler 跑出来的版本**（当时是 dbar +0.70 / dother +0.17 /
> dpar +0.35 / dperp −0.17，看起来像「共享的那半能迁移、题目专属那半不能」）。
> 用固定 filler 之后，前四条臂**全部等价**：**换一道题的向量和用自己的一样好。**

**正确的结论比之前那个更简单也更强：**
即使让向量**有机会**携带任务信息（文档排在问题之后，它的状态看得见病历），
**它承载的依然纯粹是技能**。题目专属的那一部分（`dperp`）单独注入恰好落在接收器基线上。

几何给出了原因，而且是在注入之前就能看出来的：doc-last 下同技能两道题的 `d` 余弦
在 L0 是 0.998、L8 是 0.984、L32 才降到 0.914，沿题目均值方向的能量占比从 0.997 降到 0.880。
**L8 上向量有 98% 是共享的，根本没有多少题目专属的部分可用。**
剩下那 12%（L32）到底有没有用，`spanvec-fs-dlperp`（L0/12/16/20 上跑 real,dbar,dperp）正在测。

### M10. 「可解码」和「可用」是两回事，而且差距是量化的

| 22 | **1.000** | 0.892 | 33.0 | 125.5 | 0.26 |
| 35 | 0.944 | 0.962 | 416 | 816 | 0.51 |

|---|---|---|---|---|---|
| ‖d‖/‖h‖ | 0.95 | 1.01 | **1.15** | 1.04 | 0.95 |

### M11. 参与比塌缩的深度，和移植失效的深度是**同一个深度**
PR(d)（去中心）在 L12→L16 之间从 **64 掉到 17**（PR(h_gold) 从 46 掉到 14）。
同一区间 `real` 从 ρ=1.00（L12）掉到 **0.14**（L15/16）。
→ 文档 span 的表示从「高维的逐 token 记录」塌缩成「~15 维的低秩摘要」，
  而低秩摘要不足以在一个一直在读 filler 的接收器里重建几百个 token 的算术。

⚠ 这是**对应关系**，不是机制：单材料、几何是每 4 层采一次而移植曲线恰好在塌缩处加密、
且我们没有直接干预秩。但它给出了一个可证伪的预测，**而那个预测已经被验证**（见 M13）。

### M12. 充分性和必要性给出的深度**不一样**，两者都对
- 充分性（移植）：L16 之后单层移植基本失效。
- 必要性（累积注意力屏蔽，n=20，with 0.500 / without 0.000）：
  从 L0/6/12/18 起屏蔽都压到 0.050，从 **L24** 起屏蔽 0.100，从 **L30** 起屏蔽仍然 0.300。
  也就是说，只掐掉最后 6 层对文档的注意力，就要损失 0.500→0.300。
- span 层面（n=40，with 0.550 / without 0.025）：屏蔽文档 span 0.075，
  屏蔽等长的病历 span 0.150。
→ 文档**一直被读到最后**，但**必须在前 1/3 完成交接**：单层移植是把「某一层的 span 状态」
  换掉，而下游位置在第 0..L 层已经把 filler 的内容吃进去了。
  全层同时移植 = 0.950，与 gold 齐平，正好补上这个解释。

### M13. 从几何提出的可证伪预测，被另一种格式确认了

M11 说：移植在 L12→L16 之间失效，和 PR(d) 从 64 掉到 17 是同一个区间。那是相关性。
**可证伪的预测：某种格式下若 PR 不塌缩，移植就应该撑得更深。**

doc-last 正好是这样一种格式（PR(d) 在 L16+ 是 28–33，doc-first 只有 14–17），
而且它**不是为了这个测试才选的**——它本来是用来问「向量能不能携带任务信息」的。

限制集（n=20），占各自可恢复区间的比例：

| 层 | 0 | 4 | 8 | 12 | **16** |
|---|---|---|---|---|---|
| 文档在前 | 1.00 | 1.07 | 1.14 | 1.00 | **0.14** |
| 文档在后 | 0.99 | 1.11 | 1.00 | 0.93 | **0.80** |

→ 两种格式在 L12 之前都是满效应；到 L16，**秩塌缩的那个只剩七分之一，没塌缩的那个还有五分之四**。
`dbar` 在 doc-last 的每一层都跟着 `real` 走（1.05/1.05/0.94/0.87/0.80），
所以撑得更深的**依然是 skill，不是 task**。

仍然只能叫「被确认的预测」，不能叫机制：挪动文档位置改变的不止是秩，也没有直接干预秩。
它排除掉的是「交接深度是网络的固有属性」这个读法。

### M14. 「共同偏移」占了 58% 的能量，却一点用都没有（直接回答最初的提问）

换成固定 filler（一份与题目无关的固定临床技能文档）后，几何里两个数字变了：

| | 旧（配对中性 filler） | 新（固定 filler） |
|---|---|---|
| `reldiff_d_same`（同 calculator 跨题） | 0.071 | **0.0025–0.020** ✓ 跨题无关性确认 |
| `cos(d_i, d_k)` 跨 calculator | 0.095–0.111 | **0.48–0.56** |
| `cos(d_i, 全体均值)` | — | **0.72–0.76** |
| `frac_par`（d 沿全体均值方向的能量占比） | — | **0.54–0.60** |

变化的原因是对的：用**共同**对照时，所有 `d_i = h_gold_i − h_共同filler` 共享「减去同一个 filler」
这一项，自然高度对齐；用**配对**对照时这一项各不相同，余弦被压低。
衡量「两个技能的内容向量有多不同」应当用共同对照，所以 **0.54 才是该报告的数字**。

**而这让结论更强：**
- 不同技能的内容向量余弦 0.54，**能量的 58% 落在全体共同方向上**；
- 但 `dall`（把这个共同方向单独注入）只有 **ρ = +0.11**，`dcross` 只有 **+0.06**，
  `dnear`（近亲技能）**+0.00**；
- 即：**向量里超过一半的能量是「共同偏移」，而这部分承载零。**

这正是最初那个问题（「skill 对应部分的有用部分和共同偏移」）的定量答案。

> 方法学教训：**跨条件余弦的大小由你减掉的那个对照决定**，脱离对照报告余弦没有意义。

### M15. 过程性内容承载效应，算例只承载一半（token 空间重验过）

只把 `d` 写进 span 的**前一半**：ρ = +1.06；只写**后一半**：+0.28（限制集 n=20）。
前半段与整段**逐题一致 18/20**——不是两半各承载一部分，是一半承载、另一半跟不上。

四分位（限制集）：

| span 的四分之一 | Q1 | **Q2** | Q3 | Q4 |
|---|---|---|---|---|
| ρ | +0.25 | **+0.80** | +0.12 | +0.43 |

**⚠ 章节映射必须在 token 空间里做，不能用字符比例（我第一次写错了）。**
四分位切的是 token span；而文档里散文、公式、Python 签名的 token 密度不同。
按 token 位置量，10 个 calculator 的一致结构是：

| 四分位 | 实际内容（起点范围） |
|---|---|
| Q1 (0–.25) | 标题 + Required Inputs + 计算段的**标题行**（计算段起点 0.18–0.42） |
| **Q2 (.25–.50)** | **计算段的正文——公式本身** |
| Q3 (.50–.75) | Calculation Tool（函数签名，起点 0.47–0.70）+ Example 开头（0.61–0.79） |
| Q4 (.75–1) | Example 其余部分 |

→ **过程性核心（公式正文）一段就承载了五分之四；函数签名承载零；算例承载 +0.43。**
边界逐 calculator 有浮动，所以报告的是四分位 + 章节位置分布，不声称精确对齐。
四个四分位次可加（+0.25 与 +0.80 单独 vs 前半段合起来 +1.06），所以这是定位，不是划分。

**为什么这比现有做法强：** skill-document 那条线上「哪个模块重要」一直靠**删掉模块重跑**回答，
而删模块会同时改变长度、其余部分的绝对位置和 RoPE 相位。
这里 prompt **一个 token 都没动**，只换隐状态的一段。
