# reading but cannot transfer：机制判别与正文热力图

日期：2026-10-16。设计稿；没有新增推理结果、没有启动远端任务。承接 20261015 方案，新增重点是未被单层 residual patch 覆盖的缓存历史。现稿已有逐题联合失败热力图，不需要再把同一现象换一种颜色展示。

## 1. 现在能够声称什么

现有结果是“原正确执行依赖来源，但相同深度的来源移植不能纠正指定 receiver”。这是操作性的深度分离，不是已证明的第三个算法阶段。Qwen3-0.6B/TheoremQA 有 23/92 个严格 eligible skillgroups 在总体橙区没有联合失败，不能假定每个 skill 必经三阶段。

两个识别问题：① knockout 屏蔽所有 query 到 skill keys，包括 skill 内部更新；② transfer 与 knockout 虽能配对同题，却不是同一计算历史。因此优先解释因果差异，不以 attention 权重、余弦相似度或可解码性替代因果证据。

## 2. 新代码线索：被移植的状态是否完整

已核对 `howskill/howskill/wb_patch.py:102` 的 block-output forward hook，以及 `howskill/howskill/wb_spanpatch.py:192` 的 decode_ids。patch 在 prefill 生效一次，随后撤下 hook，使用 past_key_values 自回归生成。

在 block L 输出替换 source residual 时，层 ≤L 的 K/V 已经由 receiver 计算完成，不能被该替换追溯修改；上层 source K/V 可被新状态影响。每个后续生成 token 又从底层开始计算，仍能访问未修复的低层 cache。因此“某层 source residual”不等于“完整的自回归 source 状态”。这不是已确认的代码 bug，而是当前干预定义的覆盖边界；是否解释结果需要实验。

## 3. 优先实验与可证伪结果

### P0：先确认仍在读取什么

在同题正确 donor 上分别屏蔽 reader→skill、skill→skill、两者；再分 prefill 和 decode。reader 包含题目/后续提示及生成位置，source 内行另算。先验证 identity、实际 mask 生效、合法因果位置，避免全遮蔽行产生伪分布。若只有 source-self mask 有效，则主要结论应改成来源内部计算依赖，不能继续称为持续读取。

### P1：来源 residual × 来源缓存的 2×2 修复

固定 receiver、题目、位置和层 L。S 为正确 donor 的 source span block-L residual；C 为正确 donor 的 source 位置、层≤L的 K/V。四臂为 baseline、S、C、S+C；另留完整正确 donor 与 identity patch。

先在 Qwen3-8B/MedCalc 的预先固定共同 baseline-valid 集合测试 L8、12、16、24、28；这些是设计点，不是新结果。不要按修复成功再次筛题。已有严格共同集合 n=124 可作为主诊断子集，但应同时报告较宽 baseline-valid 集合，明确条件性。支持后再补全层和第二家族。

记录完整答案准确率及第一个决策 token 的分布，区分 prefill 决策与后续 decode。S+C 相对 S 的配对提升说明未覆盖缓存有贡献；C 单独同样有效则不能归为 residual-cache 协同。交互 I=A(S+C)-A(S)-A(C)+A(base)，正值表示准确率尺度上的超加性，不足以证明唯一 AND 电路。

实现硬约束：prefill 后换 cache 不会改变已算好的首 token logits。主协议应在共同决策位置前建立 prefix cache，注入后重新计算该决策位置，并对所有臂采用完全相同的分段协议；先确认无干预分段运行与原始运行一致。若另用生成过程中换 cache，必须明确首 token 保持固定，并独立报告该估计对象。各臂深拷贝 cache，检查 token 对齐、RoPE位置、dtype 与 attention backend。关闭 use_cache 只有在每次重算都实施等价干预时才是合理对照，不能直接当作“去掉缓存混杂”。

### P2：receiver 历史是否形成进入条件

若 P1 不能解释橙区，再做 S×R：R 为同层预先指定的题目/reader residual 子集；以不含最终提示位置的题目状态为起点。不得把整段全部 donor 状态复制的成功当机制发现。若涉及历史 reader cache，必须另记为独立因子，与单层 R 区分。全状态复制仅为实现正控制。

比较 base、S、R、S+R；补同预算错误 donor、反向破坏、不同数值且不同答案的跨题 donor。S+R 强于单独二者支持状态兼容性，但还可能是答案/中间结果复制。

关键鉴别：在修复后的同一次执行里，再从更晚层 M 切断 reader→source。若救回效果再次消失，说明所移植 reader 状态没有完全替代来源需求；若不消失，仍可能只是复制了答案摘要。切断只证明路径必要性，还须 P3 识别路径传递什么。

### P3：仍在读取规则内容，还是只需要结构

构造同一 skill 的两条有效规则 f、f'，仅改变一个系数或阈值；预先计算每题 y=f(x)、y'=f'(x)，保留两者不同且两条自然 donor 都能解的题。固定题目和可见文本，在橙区把来源状态/消息改成 f' 的自然 donor 版本，测输出是否精确转向 y'，而非仅变错。需使用多个 x，使目标变化随输入变化，排除固定答案偏置；双向干预并配语义等价改写与无关字段编辑。

在 P2 修复后仍需要 source 的背景上做同一测试最有价值：reader 修复提供计算条件，而继续读到的规则内容决定答案。可进一步比较 K-only、V-only、K+V；混合 K/V 会制造不自然状态，不能从失败直接断言 routing/content 分工。此为定位补充，不是主证据。

## 4. 正文热力图：推荐“修复条件 × 深度”

推荐主图问题：晚层转移失败，究竟补回哪部分状态才能恢复？横轴实际层号；纵轴 base、S、C、S+C、R、S+R（必要时增 S+C+R，需同时有各因子对应对照）。格子为同一固定集合的答案准确率 A，不混用不同分母的 recovery。0–1 共用色标，白/浅灰到深蓝；列顶端细橙条标原始弱转移/来源依赖区间，不给数据格叠橙底。缺失实验灰色加斜线，不能填0；不按效果重新排序行或题目。

最好做两面板：左为状态修复准确率；右为同一修复臂在后续 reader→source cut 后的准确率下降 A(repair)-A(repair+cut)。两面板不能共用色标：前者[0,1]，后者用以0为中心的发散色标，容纳负值。右图切断层必须明确，可固定 M=L+1 并注明语义，或另做如下完整二维图；不要挑每格最大损伤。

更强但成本较高的备选：横轴注入/修复层 L，纵轴切断层 M，仅测 M>L，格子为同一receiver修复后再切断的准确率或准确率下降。三角之外斜线遮蔽。它把“能救回”与“救回后仍要读”放进同一执行，不再是两条边际曲线的视觉相交。不能将两条现有曲线相乘伪造二维结果，也不要跨层直接互换原始 residual 来填方阵（坐标空间与计算时间不匹配）。

图中只显示单点，遵守现有偏好；统计在附录/数据保留按 skill group 配对重采样的95%置信区间（重复抽取skill组评估估计波动），同时报告题目数和组数。稀疏组不得逐题独立抽样后夸大精度。主热力图回答机制；已有 skillgroup×layer 联合失败图回答普遍性，可保留为另图或移附录。

## 6. Open Ideas / 值得深挖的问题

**2026-10-16，候选而非已成立贡献：skill transfer 是否取决于完整执行状态，而非单层来源表示？** 触发：现有L12→L13 transfer骤降，而源依赖延续；代码仅patch prefill block输出，旧低层source KV和reader历史保留。价值：把表示失效、缓存覆盖不足、reader状态兼容三种解释可证伪地拆开。最小验证P0+P1，若不恢复再P2+P3。强结果是修复特定历史状态后晚层transfer恢复，且同次执行仍需读取可改变答案的source内容；失败模式是仅完整答案状态复制有效，或mask分离后所谓reading消失。缓存笔记、交互和时机各自已有近邻，不宜直接独立立项或承诺顶会新颖性；先做小规模判别。
