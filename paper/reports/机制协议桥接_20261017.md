# 同硬件的推理协议桥接：14组检查与两题backend对照

记录日期：2026-10-17。本记录汇总固定14组的协议桥接及固定两题的backend对照。

模型为共享盘既有 Qwen3-8B，BF16，同一张联网区 RTX 4090（49140 MiB），
torch 2.7.0a0、transformers 4.57.6。两种 attention backend 各生成 30 条记录，
max_new=1536。源码、数据及环境哈希保存在对应 manifest 中。

源码和ID哈希与本地固定版本一致。84次自身状态写回全部与对应receiver基线的
完整token序列一致；source patch与cache层数计数通过。

## 通过的检查

- eager 和 SDPA 各有 12 次自身状态写回，完整 S、分段 S、分段 SC 都与各自
  receiver 基线的 token IDs 完全一致。
- 两种 backend 的全部 60 条记录均未截断；平均生成耗时分别为 10.19、7.94 秒。
- 旧 H200 探针原始数据另已取回：40 条唯一记录、4 次 SC identity 精确一致，
  但其中一条 SC@L16 截断于 900 tokens。不能把它当作确定的机制失效。

## 不能忽略的协议差异

固定 eager 时，`medcalcbench_00987` 的 donor 完整 prefill 答对、分段 prefill
答错；`medcalcbench_00266` 的 receiver 完整 prefill 答对、分段 prefill 答错。
因此即使自身写回恒等，改变 prefill 形状也会改变这里的基线资格。

固定硬件和 full prefill 时，第二题 S@L8 在 eager 下答错，在 SDPA 下答对；
后者与旧 SDPA 审计记录的正确性一致。但第二题的 full receiver 自身也随
backend 改变正确性，故不能只挑干预输出比较，必须重新检查对应基线。

同条件跨 backend 的 30 对生成中，28 对 token 序列不同，5 对评分不同。
这些计数包含重复的 identity 条件，不是 30 个独立任务；不能据此估计全数据
的翻转率或作显著性推断。这里只确认了真实的协议敏感性。

## 正式实验的处理

继续使用启动前固定的 eager 协议和 124 个历史 ID，逐题重跑 no-skill、donor、
receiver。新主分析要求新 donor 正确、receiver 错误且 no-skill 错误；同时保留
全部固定 ID 和仅 donor/receiver 有效的结果。所有条件使用相同分段计算形状，
不将新条件直接接入旧双曲线。14组桥接已完成；四卡并行流程已接管，额外三卡正式修复正在运行，原卡处理第0分片。

主要机制对比预先固定为 L16 的 SC-S；其他层及 recut 是诊断。缺臂时拒绝生成
正式热图；截断数量、截断结果的最坏/最好界、按 skill 整组重采样的不确定性
保存在分析 JSON 中，图仅展示点估计。
