# 贡献评估、正文取舍、橙区机制实验与热力图

日期：2026-10-15。新增 GPU 实验按用户最新指示明天继续，本文档区分现有证据与待验证设计。

## 1. 客观判断

当前最有价值的贡献是**同一模型/任务条件下，技能源 span 的可转移性与源注意力依赖的深度边界分离**。六组逐层结果、共同 eligible IDs 与阈值敏感性使它超出一张单模型示意图，且对“patch failure 即上下文已利用完毕”这一推断提供具体反例。

但目前仍是**现象证据较完整、机制未识别**。它不是已证明的三阶段算法；一般的 patching 无效不等于因果不重要已有文献，context masking 与 patching 联用也已有 EMNLP 2025 先例。模型输入中的可复用文本改称 skill 不增加创新。强 A 类论文仍需要判别性机制证据，不能靠增加 rank、dose 或更多相似模型的图来代替。

现有限制包括：

1. transfer 在 wrong-skill receiver 中测，knockout 在 correct-skill run 中测。共同题目消除分母差异，**没有消除计算背景差异**。
2. 比较的是源 span 的指定移植方法，失败不等于对所有接收方和干预方式都失效。原位位置、prefill-only、wrong skill 选择均限定结论。
3. 三个模型仅两个家族，MedCalc 主筛选只剩14个 calculator groups。题目增加不自动增加独立技能组数量。
4. source skill 在 query 之前时，其状态不能包含后续 query 信息是 causal mask 的结构性质，不是独立发现。
5. 当前 knockout 实现 `howskill/howskill/wb_knockout.py:99` 的 `m[..., lo:hi] = NEG` 对所有 query 行屏蔽 skill keys，**包含 skill→skill 边**。因此当前 q 曲线同时干预 source 内部更新与后续位置读取；尚未独立证明 reader→source 边是全部效应来源。该限制已补入正文方法。
6. 尚无真实 Web/浏览器实验，因此不能把机制现象写成已验证的 Web 效率提升。

新颖性专项出处与逐篇区别见 `audit/NOVELTY-TRANSFER-ATTENTION-20261015.md`。其中最需注意的近邻是 Yang et al., *Internal Chain-of-Thought*, EMNLP 2025（https://aclanthology.org/2025.emnlp-main.1147/），其 §4.2 式7取最佳层的 cross-task transfer strength，并非当前源 span 的逐层失效/持续依赖区间。一般交互机制背景见 *The Curse of Multiple Mediators*, arXiv:2606.27510（https://arxiv.org/abs/2606.27510）。

## 3. 最优先：拆开读边与源内部计算

**问题**：橙区的knockout损伤究竟来自读不到skill，还是skill自身后续状态被破坏？

同层L、同题、同prompt、同mask kernel四条件：

- baseline：不屏蔽。
- reader→skill-only：prefill仅屏蔽query/任务等非skill位置指向skill keys的边，保持skill queries原样；decode屏蔽生成token→skill边。
- skill→skill-only：仅prefill的skill query行屏蔽skill keys，后续reader仍可读取其被改变的状态。
- 两者都屏蔽：复现当前实现。

另外加入等长非skill keys的控制；屏蔽预算和位置须报告，不能把“任何移除上下文都损伤”当skill内容专属性。Hook缺4D mask或实际没有触发应fail closed。对单层、源末层或跨边界分块单元做小probe，不假设不同模型attention mask接口相同。

可能结果：

- reader-only曲线仍有同样晚边界：橙区作为“持续读取依赖”的解释更强。
- 主要只有source-only损伤：现象应改为源内部处理/表示维护依赖，不能继续主打reader持续读取。
- 两者各有影响或存在交互：拆分报告，机制是源更新和使用的耦合。

这是先修可识别性，再谈复杂机制的必要实验。

## 4. 接收态相容性：同层2×2与反向破坏

**假说**：晚层源状态仍有用，但wrong-skill已让query/任务位置进入错误计算状态，单换source无法纠正。

同层L取四组：不换；只换skill span S；只换预先定义的query状态Q；同时换S+Q。Q在独立开发题上固定，避开最后输出瓶颈，并报告其范围。分别取早层、橙区早/中/末位置；先做少量排障，再扩现有完整eligible集合。主读数为同题paired accuracy差；交互用 raw accuracy 的 `A(S+Q)-A(S)-A(Q)+A(base)`，不混用各自归一化的rho。

可能结果：

- S与Q单独都弱、联合明显恢复；反向把错误Q移入正确运行会破坏正确source的使用：支持相容性/协同解释。
- Q单独已足够：支持任务计算状态已携带决定性信息，不能归功于S+Q协同。
- 联合无改善：不支持所选query状态解释，应检查别的缓存、位置或生成阶段。

**必要限制**：S+Q覆盖几乎全部prompt状态时是接近复制整次正确运行的平凡阳性，不能当机制发现。同题Q可能带答案，必须做query-only、跨题控制和范围预算，不能只报joint高恢复。

## 5. 在同一接收执行中先救回、再切断

**问题**：两种曲线是否只因起点不同才看起来分离？

在wrong receiver的早层Ls注入正确source，使其被救回；然后从更晚的Lm开始施加经过上一步核验的reader→skill-only knockout。只看Lm>Ls的有效网格，并和未切断的早层patch、正确运行knockout、错误运行baseline逐项配对。

可能结果：

- 早层patch能救回，但在橙区切断仍损伤，到晚层才耐受：直接显示**同一条被移植救回的计算仍需继续访问source**，减少两个运行背景不同的解释空间。
- 被救回的运行很快不再依赖source，而原正确运行仍依赖：两条轨迹可能使用不同机制；不能把两曲线当同一计算的阶段。
- 全部切断均破坏且无晚层耐受：检查token阶段和屏蔽实现，不能预设三阶段一定存在。

算力上先用约4×4三角网格而非全32×32，按probe实测速率估计GPU时长，不承诺未经实测的小时数。

## 6. 后续真正有内容的机制检验

### 6.1 prefill与decode阶段分离

同层L分别只在prefill屏蔽、只在decode屏蔽、两者都屏蔽。decode-only以未干预的正确prefill/cache为起点；记录生成截断和评分失败。

- decode-only在橙区仍强烈致损：支持逐token生成期间持续读skill。
- 只有prefill-only致损：主要是prompt内表示建立/路由依赖，不能称为生成期间反复查阅。
- 两者都有：进一步分前/中/后生成段，但不以最终答案字符串定位来事后选窗口。

### 6.2 数值/规则反事实，而不是泛化mask损伤

先挑可程序化重算答案的少量calculator；构造等长、最小变化的规则/常数对。用正确接收态，在橙区以反事实V或经核验的源表示替换对应规则内容，保留位置并尽量固定原K/路由，设置noise、等范数、无关section对照。

- 输出按替换后的公式/常数可预测改变：表明橙区确实还在使用具体skill内容，远强于仅看到mask掉分。
- 只有广泛损伤、无反事实一致性：仍可能是路由或结构破坏。
- K改变有作用而V内容替换无效：更像定位/路由机制；须核实干预覆盖，不能凭阴性判信息不存在。

该方向比随机attention热力图更有解释力，但需要额外实现和counterfactual scorer，优先级在mask拆分和2×2之后。

## 7. 热力图方案

### A. 现有数据即可完成：同题joint failure（本轮已加入正文）

- 横轴：实际层号L；纵轴：skill group，按ID固定顺序。
- 颜色：该组中“transfer回答错 且 attention-knockout回答错”的题目比例；这些题在两种协议正确skill baseline都对、transfer receiver错，knockout的无skill baseline也错。
- 六个小图：三模型×两任务；统一0–1色标，不对每个模型单独拉伸。
- 样本：MedCalc 124/84/43题，TheoremQA 61/123/64题。它比原共同IDs再次排除了transfer donor baseline本身就错的题。
- 支持：现象是否在同题内重叠、是否广泛跨skill，展示异质性。
- 不支持：不能据此识别receiver相容性，也不是attention权重图。部分组只有单题，格子颜色会二值化，不能解释成精确概率。两协议的baseline还可能不一致，原始差异字段保留在JSON。

脚本：`tools/fig_joint_failure.py`；数据：`values/joint-failure-values.json`；图：`figures/fig-joint-failure.pdf`。

### B. 最适合解释机制：干预条件×层数

- 横轴L；纵轴baseline / S-only / Q-only / S+Q。
- 主色标raw accuracy；另加一行或独立面板画2×2交互，发散色标以0为中心。
- killer pattern：橙区S-only暗、Q-only暗、joint亮，并有反向破坏证据。
- 全部prompt状态替换或query-only亮不能被装饰成协同结果。

### C. 最适合修正reading解释：边类型/阶段×层数

- 横轴L；纵轴reader→skill、skill→skill、both，以及需要时prefill-only/decode-only分面。
- 颜色为相对未干预正确运行的accuracy drop，统一越深表示损伤越大。
- 可以直接看橙区是否仍由reader边支撑，还是当前mask的source内部副作用。
- 比普通attention-weight热力图更直接，因为格子是因果干预效应。

### D. 最适合串成一条故事：注入层×后续切断层

- 横轴Ls（注入），纵轴Lm（随后切断）；Lm<=Ls未定义区灰掉。
- 颜色为同一receiver里先transfer再knockout后的accuracy或相对早层patch baseline的下降；只选一种、固定归一化。
- 早层可救回但中层切断仍失败、晚层切断恢复的区域，可将“先获得可用内容、继续依赖来源、最后耐受切断”在同一运行中连接起来。
- 需新增实验；不能用现有的两条曲线相乘或插值来伪造二维网格。

建议当前正文用A作为描述性证据，明天先跑C的必要控制，再用B检验机制；若预算足够，D作为主故事的最强桥接图。attention权重本身高不等于因果重要，不建议仅做layer×head的attention平均值作为主解释图。

## 实时反事实记录：共同题目仍有异质性

2026-10-15，新增joint-failure heatmap对严格baseline有效子集重算。Qwen3-0.6B / TheoremQA 中92个skill groups有23个在总体L11–19橙区完全没有joint failure。它说明总体双曲线的中间区间不能自动推广为每个skill/每道题必经的三阶段。正文已增加这一限制。热力图没有按效应强弱排序以制造整齐色带。

六组橙区中，组内平均joint-failure比例大于0.5的组数依次为MedCalc 13/14、17/20、11/15，TheoremQA 24/51、46/92、32/54（列顺序Qwen3-8B、Qwen3-0.6B、Mistral-7B）。这些是描述统计，不是显著性检验或普适阶段判定。
