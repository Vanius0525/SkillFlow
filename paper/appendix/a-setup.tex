\section{Experimental protocols and provenance}
\label{app:setup}

\paragraph{Tasks and scoring.}
The main MedCalc evaluation uses the $55$ calculator skills released with
SRA-Bench and $20$ questions per calculator. The benchmark scorer checks
free-form numerical answers against its prescribed tolerances. TheoremQA
uses its released prompts, skill assignments and evaluator. All main
experiments supply the selected skill directly and generate answers without
tool calls. MedCalc questions are grouped by calculator; TheoremQA questions are
grouped by skill identity.

\paragraph{Evaluation populations.}
The original candidate pool uses historical without-skill and with-skill
behavioural outcomes: rescued means wrong then right, persistent failure
means wrong in both, kept means right in both, and broken means right then
wrong. The stored MedCalc screen contains $470$ rescued IDs; the corrected
transfer battery uses $467$ from $48$ calculators after its eligibility
restrictions. The transfer code reads these frozen IDs and re-evaluates
the donor, receiver and no-skill baselines under its own protocol.

The group screen filters on the re-evaluated receiver only: every sampled
receiver answer in a retained skill group must be incorrect. It does not
filter out re-evaluated donor failures. This gives $135$ items in $14$
groups, with $124$ correct donor answers and $110$ correct layer-$8$ span
answers in Table~\ref{tab:probe}. The denominator for recovery is the
re-evaluated donor-minus-receiver gain, not historical donor accuracy.
Selection and re-evaluation are separate operations; the present evidence
does not attribute each change in correctness to one particular prompt,
backend or numerical detail.

The depth comparison intersects this transfer population with the
knockout run's own with-skill-correct, without-skill-incorrect IDs, retaining
$134$ questions. Transfer still uses its own donor and receiver outcomes,
whereas knockout retention is normalized by its own correct-baseline set.
Matching question IDs does not match the two execution protocols or make
their outcomes complements.

The mechanism study freezes the same $124$ IDs as the paired-outcome
diagnostic (Appendix~\ref{app:joint-failure}) before new inference. All
belong to the $134$-item depth intersection, but their
fresh split-prefill evaluation defines a separate population: $116$ are
donor-correct and receiver-incorrect, and $114$ also fail without the skill.
These $114$ are shared by the repair and path-cut suites. The candidate
count $124$ and Table~\ref{tab:probe}'s $124$ correct donor answers refer
to different selection stages and should not be treated as interchangeable
denominators.

The strict receiver screen selects a conditional effect; it does not
eliminate interference from the wrong skill. Appendix~\ref{app:fullscale}
reports the broader item-level receiver screen. Neither screen substitutes
for a position-matched neutral receiver intervention.

\subsection{Implementation details}
\label{app:detail}

\paragraph{Models and decoding.}
The four main models are Qwen3-8B ($36$ layers, hidden width $4096$),
Mistral-7B-Instruct-v0.3 ($32$ layers, width $4096$),
Llama-3.1-8B-Instruct ($32$ layers) and DeepSeek-LLM-7B-Chat ($30$ layers).
The supplementary Qwen3-0.6B check uses $28$ layers and width $1024$. Their full-prompt state capture and
knockout both use BF16, eager attention and $900$ new tokens, without
quantization. For DeepSeek, system instructions are merged into the user
turn. The Llama weights, configuration and vocabulary match the original
release; the public distribution supplies its tokenizer template.
For Mistral, which has no system role in its chat template, system
instructions are merged into the user turn. We use greedy decoding.
Qwen thinking mode is disabled and checked on the rendered prompt.
Attention-mask interventions use explicit attention computation with mask
checks, often called eager attention. Earlier residual-replacement runs
use PyTorch scaled dot-product attention. The mechanism experiments use
BF16, a 16-bit floating-point format, and a $1{,}536$-token generation limit.

\paragraph{Position and state checks.}
Donor and receiver prompts use length-matched skills, preserving question
positions. Residual patches replace the selected block output during
prefill. The captured positions are indexed within the prompt, separately
from any answer tokens used for scoring. Identity controls write the
receiver's own states back. A final-layer check also verifies that replacing
a position's final hidden state reproduces the donor's next-token scores
at that position. Attention cuts preserve the causal mask.

\paragraph{Focused mechanism protocol.}
A bridge on one fixed item from each of $14$ calculators compares
full-prompt prefill with prefill split before the final prompt token.
All $84$ own-state checks reproduce their corresponding receiver token
sequences exactly. Changing the prefill protocol changes one donor's and
one receiver's answer correctness. The formal repair and path comparisons
therefore use the same split protocol and fresh no-skill, donor and
receiver baselines. Truncation counts and sensitivity analyses are
retained with the result records.

\subsection{Evaluation scope and intervention provenance}
\label{app:limits}

\paragraph{Attention-mask correction.}
The original state-capture call omitted the attention mask supplied during
decoding. Although mathematically equivalent for an unpadded sequence,
these calls selected different numerical kernels. Their states differed
by $1.2\%$ at layer $8$ and $25\%$ at layer $34$.
Identity patching changed $108/1{,}766$ Qwen3-8B outcomes ($6.1\%$).
Matching the masks restores exact identity agreement, including all
$467$ items in the corrected MedCalc rerun. All main-text state interventions
use this correction. Attention knockout operates directly on attention
masks and uses no donor-state capture.

\paragraph{Development and replication.}
The initial MedCalc intervention battery sampled four rescued questions
from each of the $40$ calculators with the most eligible questions.
The corrected full-data rerun uses every rescued question from calculators
with at least two, giving $467$ items from $48$ calculators.
The main receiver screen then retains $135$ questions from $14$ calculators.
Historical development results retain their original sample labels.
Table~\ref{tab:fullscale} shows the corrected rerun alongside the earlier
screened subset. The main depth study currently covers six verified model--task
comparisons across four models and families, with two TheoremQA cells
pending. A seventh verified comparison uses Qwen3-0.6B on MedCalc as a
supplementary scale check. Each comparison uses common eligible items
for the two intervention types. The new-family candidate pools
inherit the earlier models' selection, so their results are conditional
rather than full-benchmark estimates.

\paragraph{Scientific scope.}
The experiments characterize supplied skill instructions under fixed
selection and controlled generation. The depth ordering holds for the
reported conditional populations and protocols. Historical transfer and
knockout differ in backend; the added families use matching eager-attention
protocols. The cache-repair and path-specific tests provide a focused
result on Qwen3-8B/MedCalc. All-query skill knockout combines access from post-skill tokens with
skill-state updates; its full-depth profile cannot be interpreted as
post-skill-only dependence. Prefill and decoding are jointly intervened on,
so phase-specific claims require separate tests. The stored paired-outcome diagnostic supports same-question joint
failures in three MedCalc settings; it does not extend that evidence to
all completed comparisons.
Interactive browser tasks, skill retrieval errors and learned state
compression are natural settings in which to test how these findings
extend to agent systems.
