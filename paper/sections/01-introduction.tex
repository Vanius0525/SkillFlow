\section{Introduction}
\label{sec:intro}

Agent skills are becoming an important source of capability for Web agents.
We use \emph{skill} in Anthropic's Agent Skills sense: a package of task
instructions, scripts and supporting resources, organized around a
\texttt{SKILL.md} entry point that an agent discovers and loads when relevant
\citep{zhang2025agentskills}. The Web supplies procedural material for such
skills---site instructions, worked examples, API documentation and
step-by-step guides---that can enter an agent's context without changing its
weights. Web retrieval brings external content into context
\citep{tan2025htmlrag}, while Web-agent systems retrieve reusable
workflows from past trajectories \citep{wang2024awm} and combine action
programs with natural-language skill guidance \citep{wang2026webxskill}.
Skills therefore turn external expertise into an operational source of agent
capability. Understanding what the model acquires when it reads a skill is
central to making that capability reusable.

When a model successfully follows a newly supplied skill, what
ability has it acquired? Has the context provided an internal skill that can
be extracted and reused, or an ability sustained by the original instructions
and computation? This question matters as agents retrieve, share and reuse
skills across tasks: successful execution demonstrates that a skill can be
used, but does not establish how independently its internal representation
can operate. We study this distinction through the instruction content loaded from
skills, asking how the ability to reuse their states relates to the
ongoing need to access their source.

A natural way to test an internal skill is to move its states to another
execution and ask whether they recover the ability. Task and function
vectors show that such transfer can work \citep{hendel2023taskvectors,
todd2024functionvectors, davidson2025prompting, bigoulaeva2026instructionvectors}.
If a transferable state carries the skill's contribution, losing its effect
might suggest that the model has finished using the source. But another
possibility is more consequential: the source may still be needed, while
its states no longer work in a different computation. We distinguish these
possibilities by asking two questions together: \emph{can the skill states
correct another execution, and does the original execution still need access
to the skill?} Figure~\ref{fig:teaser} illustrates the tests and their separation.

Prior work demonstrates transferable task states, layer-wise subtask
scheduling and composable skill caches
\citep{hendel2023taskvectors,yang2025internalcot,li2026prefillnotes}.
We ask a complementary question: \emph{when a source remains necessary, how
far can its states be reused, and what restores reuse when it fails?}

We answer these questions with complementary interventions along model
depth. State replacement transplants the correct skill's span states into
an equal-length wrong-skill receiver and measures recovered task performance.
Cumulative attention knockout blocks subsequent attention to the skill in
the original correct-skill run and measures retained performance. An effective
transfer probe is essential: on a screened clinical-calculator subset,
early source-span replacement recovers $0.89$ of the correct skill's gain,
whereas final-position replacement has little effect. Content, position and
cross-question controls establish that this recovery carries structured
skill content.

Our main finding is a clear separation between \emph{using} and \emph{reusing}
a contextual skill. On Qwen3-8B and MedCalc, transfer drops below half of the
available gain at layer $13$ of $36$, while subsequent skill attention remains
important until layer $25$. Between these boundaries, the model still needs
the source, but transplanting its states has little corrective effect in the
receiver. \textbf{A skill can remain useful to its original computation after
its states cease to be effectively reusable.} This ordering recurs across
all six tested combinations of three models and two task domains, including
evaluation on common eligible items. Repeating late replacement does not
restore early transfer. The results challenge a single progression from
reading a skill to possessing an independently reusable internal version:
source use and state reuse follow different depth profiles.

The separation also exposes a role for computation history. On Qwen3-8B
and MedCalc, replacing both source states and their attention caches raises
layer-$16$ accuracy from $3.5\%$ to $42.1\%$. Cutting subsequent
reader-to-source attention reduces it to $7.0\%$. Separate path cuts
confirm that late dependence reflects continued reading rather than only
source-internal updates (\S\ref{sec:mechanism}). Thus a useful skill state
can require both compatible cached history and continued access to the source.

We make three contributions:
\begin{enumerate}\itemsep0pt\parskip0pt
\item \textbf{A validated probe of internal skill reuse.}
Source-span interventions recover the correct skill's benefit, while matched
content, position and cross-question controls identify the structured skill
information responsible for recovery
(\S\ref{sec:battery}).
\item \textbf{A depth-wise separation between skill transfer and source use.}
Paired transfer and attention-knockout sweeps reveal an intermediate interval
in which skill states transfer poorly even though the original computation
continues to depend on the source
(\S\ref{sec:depth}).
\item \textbf{A causal test of computational history and continued reading.}
Joint source-state and cache repair recovers substantial late transfer,
while reader recutting removes most of that recovery at layer $16$.
Path-specific cuts distinguish continued source reading from source-internal
updates, explaining why useful skill information need not be independently
reusable (\S\ref{sec:mechanism}).
\end{enumerate}
